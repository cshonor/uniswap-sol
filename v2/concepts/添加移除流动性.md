# Uniswap V2 添加/移除流动性详解

本文档详细说明 Uniswap V2 中添加和移除流动性的机制、计算方式和注意事项。

## 📋 概述

流动性是 Uniswap V2 的核心，用户可以通过添加流动性成为流动性提供者（LP），获得 LP tokens 和手续费收益。

---

## 🪙 什么是 LP Token？

### 定义

**LP Token（Liquidity Provider Token，流动性提供者代币）** 是用户在添加流动性后获得的**凭证代币**，代表用户在流动性池中的**份额**。

### 本质

LP Token 本质上是一个 **ERC20 代币**，具有以下特点：

1. **代表份额**：
   - LP Token 数量 = 你在池子中的份额比例
   - 例如：如果池子总共有 1000 LP tokens，你持有 100 LP tokens，那么你的份额 = 10%

2. **可转让**：
   - LP Token 是标准的 ERC20 代币，可以转账、交易
   - 可以发送给其他地址，也可以在其他 DEX 上交易

3. **可销毁**：
   - 移除流动性时，LP Token 会被销毁
   - 销毁后，你可以取回对应的代币和手续费收益

### 作用

**LP Token 的主要作用：**

1. **证明所有权**：
   - 证明你在这个流动性池中投入了多少资金
   - 证明你拥有多少份额

2. **计算收益**：
   - 手续费收益按 LP Token 份额分配
   - 你的收益 = 总手续费 × (你的 LP Token / 总 LP Token)

3. **流动性挖矿（Liquidity Mining）**：
   - 可以将 LP Token 质押到其他协议（如流动性挖矿项目）
   - 获得额外的代币奖励
   
   **详细说明**：
   
   **什么是流动性挖矿？**
   - 流动性挖矿是一种激励机制，项目方为了吸引流动性提供者，会奖励额外的代币
   - 你提供流动性 → 获得 LP Token → 质押 LP Token → 获得奖励代币
   
   **为什么可以质押 LP Token？**
   - LP Token 是标准的 ERC20 代币，可以被其他智能合约接受
   - 其他协议可以验证你确实提供了流动性（通过检查 LP Token 余额）
   - 质押后，LP Token 被锁定在挖矿合约中，你无法转移，但可以随时取消质押
   
   **质押到其他协议是什么意思？**
   - 例如：Compound、Aave、SushiSwap 等 DeFi 协议
   - 这些协议会创建"流动性挖矿池"
   - 你将 LP Token 存入这些池子，协议会按时间给你发放奖励代币
   
   **完整流程示例**：
   1. 你在 Uniswap 添加流动性：投入 1000 DAI + 2000 USDT → 获得 1414 LP Token
   2. 你将 1414 LP Token 质押到 SushiSwap 的流动性挖矿池
   3. SushiSwap 每天给你发放 SUSHI 代币奖励（例如每天 10 SUSHI）
   4. 你的收益 = Uniswap 手续费 + SUSHI 奖励
   5. 随时可以取消质押，取回 LP Token
   
   **双重收益**：
   - ✅ **交易手续费**：来自 Uniswap 池子的交易手续费（按 LP Token 份额分配）
   - ✅ **挖矿奖励**：来自流动性挖矿项目的额外代币奖励
   
   **风险提示**：
   - ⚠️ 质押的 LP Token 可能被锁定一段时间
   - ⚠️ 挖矿奖励的代币价格可能波动
   - ⚠️ 需要评估挖矿项目的安全性

4. **移除流动性**：
   - 只有持有 LP Token 才能移除流动性
   - 移除时，LP Token 被销毁，你获得对应的代币

### 计算方式

**首次添加流动性**：
```
LP Token 数量 = √(amount0 × amount1)
```

**后续添加流动性**：
```
新增 LP Token = min(
    (amount0 × totalSupply) / reserve0,
    (amount1 × totalSupply) / reserve1
)
```

其中：
- `totalSupply`：当前 LP Token 的总供应量
- `reserve0`, `reserve1`：池子中两种代币的储备量

### 示例

**场景**：你向 DAI/USDT 池子添加流动性

1. **初始状态**：
   - 池子：1000 DAI + 2000 USDT
   - 总 LP Token：1414

2. **你添加流动性**：
   - 投入：500 DAI + 1000 USDT
   - 获得：707 LP Token（按比例计算）

3. **你的份额**：
   - 你的份额 = 707 / (1414 + 707) = 33.3%
   - 池子总价值增加，但价格不变

4. **手续费收益**：
   - 如果池子产生 100 USDT 的手续费
   - 你的收益 = 100 × 33.3% = 33.3 USDT

5. **移除流动性**：
   - 销毁 707 LP Token
   - 取回：500 DAI + 1000 USDT + 对应的手续费收益

### 重要理解

✅ **LP Token = 你在池子中的"股份"**
- 就像公司的股票，代表你的所有权份额
- 份额越大，收益越多

✅ **LP Token 数量 ≠ 代币数量**
- LP Token 是独立的代币
- 它的价值取决于池子的总价值和你的份额

✅ **LP Token 可以增值**
- 随着手续费累积，池子总价值增加
- 你的 LP Token 对应的代币价值也会增加

✅ **LP Token 有风险**
- 如果代币价格波动，可能出现无常损失
- LP Token 的价值会随池子价值变化

## ➕ 添加流动性

### Uniswap V2 添加流动性的执行流程

当用户在 Uniswap V2 中添加流动性时，涉及三个核心合约的交互：**Router（路由合约）**、**Factory（工厂合约）** 和 **Pair（交易对合约）**。

**完整执行流程（6个步骤）：**

```
用户 (User)
  ↓
1. addLiquidity()  ← 调用 Router 合约的 addLiquidity 函数
  ↓
Router 合约
  ↓
2. getPair() / createPair()  ← Router 调用 Factory 合约
  ↓
Factory 合约
  ↓
3. create2  ← Factory 使用 CREATE2 创建 Pair 合约（如果不存在）
  ↓
DAI/WETH Pair 合约
  ↑
4. transferFrom()  ← Router 将用户的代币转移到 Pair 合约
  ↑
Router 合约
  ↑
5. mint()  ← Router 调用 Pair 合约的 mint 函数铸造 LP Token
  ↑
DAI/WETH Pair 合约
  ↓
6. transfer LP Token  ← Pair 合约将 LP Token 转给用户
  ↓
用户 (User)  ← 收到 LP Token
```

**详细步骤说明：**

1. **用户调用 Router 的 `addLiquidity`**
   - 用户调用 Router 合约的 `addLiquidity` 函数
   - 传入参数：`tokenA`, `tokenB`, `amountADesired`, `amountBDesired`, `amountAMin`, `amountBMin`, `to`, `deadline`
   - Router 合约负责协调整个流程

2. **Router 调用 Factory 的 `getPair` 和 `createPair`**
   - Router 首先调用 Factory 的 `getPair(tokenA, tokenB)` 检查交易对是否已存在
   - 如果不存在，Router 调用 Factory 的 `createPair(tokenA, tokenB)` 创建新的交易对
   - Factory 负责管理所有交易对合约

3. **Factory 使用 CREATE2 创建 Pair 合约**
   - Factory 使用 Solidity 的 `CREATE2` 操作码创建新的 Pair 合约
   - CREATE2 确保相同参数下创建的合约地址是确定性的
   - 新创建的 Pair 合约管理 DAI/WETH 的流动性池

4. **Router 调用 `transferFrom` 转移代币**
   - Router 调用 `tokenA.transferFrom(user, pair, amountA)` 将用户的 tokenA 转移到 Pair 合约
   - Router 调用 `tokenB.transferFrom(user, pair, amountB)` 将用户的 tokenB 转移到 Pair 合约
   - 注意：用户需要先授权（approve）Router 合约才能转移代币

5. **Router 调用 Pair 的 `mint` 函数**
   - Router 调用 Pair 合约的 `mint(to)` 函数
   - Pair 合约计算应该铸造多少 LP Token（使用 `min(liquidity0, liquidity1)` 公式）
   - Pair 合约更新储备量（`reserve0`, `reserve1`）

6. **Pair 将 LP Token 转给用户**
   - Pair 合约调用 `_mint(to, liquidity)` 铸造 LP Token
   - LP Token 直接转给用户指定的地址（`to` 参数）
   - 用户收到 LP Token，代表在池子中的份额

**关键理解：**

- ✅ **Router 是协调者**：不持有资金，只负责协调各个合约的交互
- ✅ **Factory 是管理者**：负责创建和管理所有交易对合约
- ✅ **Pair 是执行者**：实际持有代币储备，执行添加流动性和铸造 LP Token
- ✅ **用户需要先授权**：在调用 `addLiquidity` 之前，用户需要先调用 `tokenA.approve(router, amountA)` 和 `tokenB.approve(router, amountB)`

**代码示例：**

```solidity
// 1. 用户先授权 Router 合约
IERC20(tokenA).approve(router, amountA);
IERC20(tokenB).approve(router, amountB);

// 2. 用户调用 Router 的 addLiquidity
router.addLiquidity(
    tokenA,
    tokenB,
    amountADesired,
    amountBDesired,
    amountAMin,
    amountBMin,
    to,
    deadline
);
```

### Router.addLiquidity 源码逐行解析

下面我们详细解析 Uniswap V2 Router 合约中 `addLiquidity` 函数的每一行代码，看看它是如何实现上述 6 步流程的。

**完整的函数签名：**

```solidity
function addLiquidity(
    address tokenA,
    address tokenB,
    uint amountADesired,
    uint amountBDesired,
    uint amountAMin,
    uint amountBMin,
    address to,
    uint deadline
) external virtual override ensure(deadline) returns (uint amountA, uint amountB, uint liquidity)
```

**函数体逐行解析：**

#### 第 1 行：计算最优代币数量

```solidity
(amountA, amountB) = _addLiquidity(tokenA, tokenB, amountADesired, amountBDesired, amountAMin, amountBMin);
```

**作用**：
- 调用内部函数 `_addLiquidity`，计算实际要使用的代币数量
- 这一步**只在 Router 内部计算**，不涉及任何代币转移
- 根据当前池子的储备量比例，计算最优的配对数量

**`_addLiquidity` 内部逻辑**：

```solidity
function _addLiquidity(
    address tokenA,
    address tokenB,
    uint amountADesired,
    uint amountBDesired,
    uint amountAMin,
    uint amountBMin
) internal returns (uint amountA, uint amountB) {
    // 1. 获取当前池子的储备量
    (uint reserveA, uint reserveB) = getReserves(factory, tokenA, tokenB);
    
    if (reserveA == 0 && reserveB == 0) {
        // 首次添加流动性：使用用户提供的全部数量
        (amountA, amountB) = (amountADesired, amountBDesired);
    } else {
        // 后续添加：计算最优配对数量，保持比例
        uint amountBOptimal = quote(amountADesired, reserveA, reserveB);
        
        if (amountBOptimal <= amountBDesired) {
            // 情况 1：用户提供的 B 代币足够
            require(amountBOptimal >= amountBMin, "UniswapV2Router: INSUFFICIENT_B_AMOUNT");
            (amountA, amountB) = (amountADesired, amountBOptimal);
        } else {
            // 情况 2：用户提供的 B 代币不足，反过来计算
            uint amountAOptimal = quote(amountBDesired, reserveB, reserveA);
            require(amountAOptimal >= amountAMin, "UniswapV2Router: INSUFFICIENT_A_AMOUNT");
            (amountA, amountB) = (amountAOptimal, amountBDesired);
        }
    }
}
```

**关键理解**：
- ✅ 这一步**只计算，不转账**
- ✅ 确保 `amountA / amountB = reserveA / reserveB`（保持价格不变）
- ✅ 多余的代币会被"标记"为退回（实际退回在后续步骤处理）

**对应流程步骤**：这一步对应文档中的"Router 内部计算最优数量"

---

#### 第 2 行：获取 Pair 合约地址

```solidity
address pair = UniswapV2Library.pairFor(factory, tokenA, tokenB);
```

**作用**：
- 使用 `UniswapV2Library.pairFor` 函数计算或获取 Pair 合约地址
- 这个函数内部会调用 `Factory.getPair(tokenA, tokenB)`
- 如果 Pair 不存在，`pairFor` 会返回零地址（但实际使用中，Router 会在调用前确保 Pair 已创建）

**`pairFor` 函数逻辑**：

```solidity
// 在 UniswapV2Library 中
function pairFor(address factory, address tokenA, address tokenB) internal pure returns (address pair) {
    (address token0, address token1) = sortTokens(tokenA, tokenB);
    pair = address(uint160(uint256(keccak256(abi.encodePacked(
        hex'ff',
        factory,
        keccak256(abi.encodePacked(token0, token1)),
        hex'96e8ac4277198ff8b6f785478aa9a39f403cb768dd02cbee326c3e7da348845f' // Pair 合约的 init code hash
    )))));
}
```

**关键理解**：
- ✅ 使用 CREATE2 的地址计算方式，可以**预测** Pair 合约地址
- ✅ 即使 Pair 还没创建，也能计算出它的地址
- ✅ 这允许在链下预先计算地址，提高效率

**对应流程步骤**：这一步对应文档中的"步骤 2：Router 调用 Factory 的 getPair/createPair"

---

#### 第 3 行：转移 tokenA 到 Pair 合约

```solidity
TransferHelper.safeTransferFrom(tokenA, msg.sender, pair, amountA);
```

**作用**：
- 使用 `TransferHelper.safeTransferFrom` 安全地将 `amountA` 数量的 `tokenA` 从用户（`msg.sender`）转移到 Pair 合约（`pair`）
- `TransferHelper` 是一个工具库，封装了安全的代币转移逻辑

**`safeTransferFrom` 内部逻辑**：

```solidity
library TransferHelper {
    function safeTransferFrom(
        address token,
        address from,
        address to,
        uint value
    ) internal {
        // 调用 ERC20 的 transferFrom
        (bool success, bytes memory data) = token.call(
            abi.encodeWithSelector(0x23b872dd, from, to, value)
        );
        require(success && (data.length == 0 || abi.decode(data, (bool))), "TransferHelper: TRANSFER_FROM_FAILED");
    }
}
```

**关键理解**：
- ✅ 这一步**真正执行代币转移**
- ✅ 从用户的账户扣除 `amountA` 数量的 `tokenA`
- ✅ 代币进入 Pair 合约的账户
- ✅ 用户需要先调用 `approve(router, amountA)` 授权

**对应流程步骤**：这一步对应文档中的"步骤 4：Router 调用 transferFrom 转移用户的代币到 Pair 合约"

---

#### 第 4 行：转移 tokenB 到 Pair 合约

```solidity
TransferHelper.safeTransferFrom(tokenB, msg.sender, pair, amountB);
```

**作用**：
- 与第 3 行相同，但转移的是 `tokenB`
- 将 `amountB` 数量的 `tokenB` 从用户转移到 Pair 合约

**关键理解**：
- ✅ 与第 3 行逻辑相同，只是代币不同
- ✅ 两步转移完成后，Pair 合约收到了两种代币

**对应流程步骤**：这一步也对应文档中的"步骤 4：Router 调用 transferFrom 转移用户的代币到 Pair 合约"

---

#### 第 5 行：调用 Pair 的 mint 函数

```solidity
liquidity = IUniswapV2Pair(pair).mint(to);
```

**作用**：
- 调用 Pair 合约的 `mint` 函数
- `mint` 函数会：
  1. 计算应该铸造多少 LP Token（使用 `min(liquidity0, liquidity1)` 公式）
  2. 铸造 LP Token 并转给 `to` 地址
  3. 更新 Pair 合约的储备量（`reserve0`, `reserve1`）

**Pair.mint 函数内部逻辑**：

```solidity
function mint(address to) external lock returns (uint liquidity) {
    // 1. 获取当前储备量
    (uint112 _reserve0, uint112 _reserve1,) = getReserves();
    uint balance0 = IERC20(token0).balanceOf(address(this));
    uint balance1 = IERC20(token1).balanceOf(address(this));
    
    // 2. 计算新增的代币数量
    uint amount0 = balance0 - _reserve0;
    uint amount1 = balance1 - _reserve1;
    
    // 3. 计算应该铸造的 LP Token 数量
    bool feeOn = _mintFee(_reserve0, _reserve1);
    uint _totalSupply = totalSupply;
    
    if (_totalSupply == 0) {
        // 首次添加流动性
        liquidity = Math.sqrt(amount0 * amount1) - MINIMUM_LIQUIDITY;
        _mint(address(0), MINIMUM_LIQUIDITY); // 永久锁定最小流动性
    } else {
        // 后续添加流动性
        liquidity = Math.min(
            (amount0 * _totalSupply) / _reserve0,
            (amount1 * _totalSupply) / _reserve1
        );
    }
    
    require(liquidity > 0, "UniswapV2: INSUFFICIENT_LIQUIDITY_MINTED");
    
    // 4. 铸造 LP Token 给 to 地址
    _mint(to, liquidity);
    
    // 5. 更新储备量
    _update(balance0, balance1, _reserve0, _reserve1);
    
    emit Mint(msg.sender, amount0, amount1);
}
```

**关键理解**：
- ✅ `mint` 函数会**自动计算** LP Token 数量
- ✅ 使用 `min(liquidity0, liquidity1)` 确保价格不变
- ✅ LP Token 直接转给 `to` 地址（通常是用户）
- ✅ 更新储备量，完成整个流程

**对应流程步骤**：这一步对应文档中的"步骤 5：Router 调用 Pair 的 mint 函数"和"步骤 6：Pair 将 LP Token 转给用户"

### 完整代码流程总结

```
用户调用 Router.addLiquidity()
    ↓
1. _addLiquidity() → 计算最优代币数量（只计算，不转账）
    ↓
2. pairFor() → 获取 Pair 合约地址
    ↓
3. safeTransferFrom(tokenA) → 转移 tokenA 到 Pair
    ↓
4. safeTransferFrom(tokenB) → 转移 tokenB 到 Pair
    ↓
5. Pair.mint(to) → Pair 计算并铸造 LP Token，转给用户
    ↓
完成！用户收到 LP Token
```

**关键点总结**：

1. ✅ **第 1 步是纯计算**：不涉及任何代币转移，只计算最优数量
2. ✅ **第 2 步获取地址**：使用 CREATE2 可以预测 Pair 地址
3. ✅ **第 3-4 步真正转账**：代币从用户转移到 Pair 合约
4. ✅ **第 5 步完成铸造**：Pair 合约计算 LP Token 并转给用户
5. ✅ **多余代币的处理**：如果用户提供的代币比例不匹配，`_addLiquidity` 会计算出实际使用的数量，多余的代币会留在用户账户（因为只转移了 `amountA` 和 `amountB`，而不是 `amountADesired` 和 `amountBDesired`）

### 核心原则

**添加流动性的两个重要原则：**

1. **初始流动性决定代币价格**
   - 首次添加流动性时，两种代币的数量比例决定了初始价格
   - 价格 = `amount1 / amount0`

2. **添加流动性不能影响价格**
   - 后续添加流动性时，必须按照当前池中的代币比例添加
   - 保持比例：`(x + dx) / (y + dy) = x / y`

### 价格不变性的数学证明

**基础关系**：
```
x · y = k = L²
```

其中：
- `x`：token0 的储备量
- `y`：token1 的储备量
- `k`：恒定乘积
- `L`：流动性（`L = √k = √(x · y)`）

**价格不变性公式**：

添加流动性时，必须满足：

```
y₀ / x₀ = (y₀ + dy) / (x₀ + dx)
```

**推导过程**：

1. **初始状态**：
   - 储备量：`x₀`, `y₀`
   - 价格：`P₀ = y₀ / x₀`
   - 恒定乘积：`k₀ = x₀ · y₀`
   - 流动性：`L₀ = √k₀ = √(x₀ · y₀)`

2. **添加流动性后**：
   - 新增储备量：`dx`, `dy`
   - 新储备量：`x₀ + dx`, `y₀ + dy`
   - 新价格：`P₁ = (y₀ + dy) / (x₀ + dx)`
   - 新恒定乘积：`k₁ = (x₀ + dx) · (y₀ + dy)`
   - 新流动性：`L₁ = √k₁ = √((x₀ + dx) · (y₀ + dy))`

3. **价格不变的条件**：
   ```
   P₁ = P₀
   (y₀ + dy) / (x₀ + dx) = y₀ / x₀
   ```

4. **交叉相乘**：
   ```
   (y₀ + dy) · x₀ = y₀ · (x₀ + dx)
   y₀ · x₀ + dy · x₀ = y₀ · x₀ + y₀ · dx
   dy · x₀ = y₀ · dx
   ```

5. **得到比例关系**：
   ```
   dy / dx = y₀ / x₀
   ```

**结论**：
- ✅ 添加流动性时，新增代币的比例必须等于当前池子的比例
- ✅ 即：`dy / dx = y₀ / x₀`，等价于 `y₀ / x₀ = (y₀ + dy) / (x₀ + dx)`
- ✅ 这确保了价格保持不变：`P₁ = P₀`

**图形表示**：
- 在 `x-y` 坐标图中，价格 `P = y / x` 表示从原点到点 `(x, y)` 的斜率
- 添加流动性时，从点 `(x₀, y₀)` 移动到点 `(x₀ + dx, y₀ + dy)`
- 如果两个点在同一条从原点出发的直线上（斜率相同），则价格不变

### 首次添加流动性

**投入 dx, dy，获取 LP Token**

当用户投入 `dx` 数量的 token0 和 `dy` 数量的 token1 时，会获得 LP Token。

**公式：**

根据基础关系 `x · y = k = L²`，首次添加流动性时：

```
③ L₀ = √(x₀ · y₀)
```

其中：
- `x₀ = dx`：投入的 token0 数量
- `y₀ = dy`：投入的 token1 数量
- `L₀`：获得的 LP Token 数量

**代码实现：**
```solidity
liquidity = sqrt(amount0 * amount1)
```

**示例：**
- 投入：`dx = 1000` DAI, `dy = 2000` USDT
- 初始价格：`P₀ = dy / dx = 2000 / 1000 = 2` USDT/DAI
- LP tokens：`L₀ = √(1000 × 2000) = √2,000,000 ≈ 1414`

**特点：**
- 初始流动性决定了代币价格
- LP tokens 数量 = 两种代币数量的几何平均数
- LP Token 可以用于流动性挖矿等用途

### 后续添加流动性

**投入 dx, dy，获取 LP Token**

当池子已存在时，用户投入 `dx` 和 `dy`，需要满足价格不变性条件。

**前提条件**（价格不变性）：

```
① y₀ / x₀ = (y₀ + dy) / (x₀ + dx)
```

**流动性计算**：

添加流动性后，新流动性为：

```
② L₁ = √((x₀ + dx) · (y₀ + dy))
```

新增的 LP Token 数量：

```
ΔL = L₁ - L₀ = √((x₀ + dx) · (y₀ + dy)) - √(x₀ · y₀)
```

**实际计算方式**（代码实现）：

由于需要保持价格不变，使用比例计算：

```solidity
liquidity0 = (amount0 * totalSupply) / reserve0
liquidity1 = (amount1 * totalSupply) / reserve1
liquidity = min(liquidity0, liquidity1)  // 这就是新增的 LP Token 数量
```

**重要理解**：`liquidity` 就是用户获得的 **LP Token 数量**！

**为什么使用 `min(liquidity0, liquidity1)`？**

这是为了**确保价格不变**，同时**最大化使用用户提供的代币**。

**核心原理**：

1. **`liquidity0` 的含义**：
   - 如果按照 `amount0` 的比例添加，可以铸造多少 LP tokens
   - `liquidity0 = (amount0 * totalSupply) / reserve0`
   - 公式含义：`amount0` 占 `reserve0` 的比例 × 当前 LP token 总量 = 可以获得的 LP token 数量
   - 表示：如果只考虑 token0，可以铸造多少 LP tokens

2. **`liquidity1` 的含义**：
   - 如果按照 `amount1` 的比例添加，可以铸造多少 LP tokens
   - `liquidity1 = (amount1 * totalSupply) / reserve1`
   - 公式含义：`amount1` 占 `reserve1` 的比例 × 当前 LP token 总量 = 可以获得的 LP token 数量
   - 表示：如果只考虑 token1，可以铸造多少 LP tokens

3. **`min(liquidity0, liquidity1)` 的含义**：
   - 这是用户实际获得的 **LP Token 数量**
   - 取最小值确保只使用能够保持价格不变的那部分代币
   - 多余的代币会被退回

3. **为什么要取最小值？**

**情况 1：比例完全匹配**（理想情况）
- 如果 `dy / dx = y₀ / x₀`，则 `liquidity0 = liquidity1`
- 取 `min(liquidity0, liquidity1)` = `liquidity0` = `liquidity1`
- 所有代币都被使用，价格不变 ✓

**情况 2：比例不匹配**（实际情况）
- 如果 `dy / dx > y₀ / x₀`（token1 过多）
  - `liquidity0 < liquidity1`
  - 取 `min(liquidity0, liquidity1)` = `liquidity0`
  - 只使用 `liquidity0` 对应的 token0 和 token1
  - 多余的 token1 会被退回
  - 价格不变 ✓

- 如果 `dy / dx < y₀ / x₀`（token0 过多）
  - `liquidity1 < liquidity0`
  - 取 `min(liquidity0, liquidity1)` = `liquidity1`
  - 只使用 `liquidity1` 对应的 token0 和 token1
  - 多余的 token0 会被退回
  - 价格不变 ✓

**数学关系**：

```
liquidity0 = (dx * L₀) / x₀
liquidity1 = (dy * L₀) / y₀
```

**关键理解**：
- 如果 `dy / dx = y₀ / x₀`（比例匹配），则 `liquidity0 = liquidity1`
- 如果 `dy / dx ≠ y₀ / x₀`（比例不匹配），则 `liquidity0 ≠ liquidity1`
- **取最小值确保只使用能够保持价格不变的那部分代币**
- **多余的代币会被退回给用户**

**示例说明**：

假设当前池子：`x₀ = 1000` DAI, `y₀ = 2000` USDT, `L₀ = 1414`

**示例 1：比例匹配**
- 投入：`dx = 500` DAI, `dy = 1000` USDT
- `liquidity0 = (500 * 1414) / 1000 = 707`（如果只考虑 DAI，可获得 707 LP tokens）
- `liquidity1 = (1000 * 1414) / 2000 = 707`（如果只考虑 USDT，可获得 707 LP tokens）
- `liquidity = min(707, 707) = 707`（**实际获得的 LP Token 数量 = 707**）
- 所有代币都被使用 ✓

**示例 2：token1 过多**
- 投入：`dx = 500` DAI, `dy = 1500` USDT（比例不匹配）
- `liquidity0 = (500 * 1414) / 1000 = 707`（如果只考虑 DAI，可获得 707 LP tokens）
- `liquidity1 = (1500 * 1414) / 2000 = 1060.5`（如果只考虑 USDT，可获得 1060.5 LP tokens）
- `liquidity = min(707, 1060.5) = 707`（**实际获得的 LP Token 数量 = 707**）
- 实际使用：500 DAI + 1000 USDT（按比例，对应 707 LP tokens）
- 退回：500 USDT（多余的）
- 价格不变 ✓

**示例 3：token0 过多**
- 投入：`dx = 1000` DAI, `dy = 1000` USDT（比例不匹配）
- `liquidity0 = (1000 * 1414) / 1000 = 1414`（如果只考虑 DAI，可获得 1414 LP tokens）
- `liquidity1 = (1000 * 1414) / 2000 = 707`（如果只考虑 USDT，可获得 707 LP tokens）
- `liquidity = min(1414, 707) = 707`（**实际获得的 LP Token 数量 = 707**）
- 实际使用：500 DAI + 1000 USDT（按比例，对应 707 LP tokens）
- 退回：500 DAI（多余的）
- 价格不变 ✓

**总结**：
- ✅ `liquidity0` 和 `liquidity1` 都表示**可以获得的 LP Token 数量**
- ✅ `min(liquidity0, liquidity1)` 是用户**实际获得的 LP Token 数量**
- ✅ 取最小值确保 LP Token 数量与使用的代币比例一致
- ✅ 多余的代币会被退回，不会影响 LP Token 的计算

**示例：**
- 当前池子：`x₀ = 1000` DAI, `y₀ = 2000` USDT
- 当前流动性：`L₀ = √(1000 × 2000) = 1414`
- 投入：`dx = 500` DAI, `dy = 1000` USDT（按比例）

**计算**：
```
liquidity0 = (500 * 1414) / 1000 = 707
liquidity1 = (1000 * 1414) / 2000 = 707
liquidity = min(707, 707) = 707
```

**验证**：
```
新流动性：L₁ = √((1000 + 500) × (2000 + 1000)) = √(1500 × 3000) = √4,500,000 ≈ 2121
新增流动性：ΔL = 2121 - 1414 = 707 ✓
```

**结果：**
- 新池子：1500 DAI + 3000 USDT
- 新 LP tokens：1414 + 707 = 2121
- 价格保持不变：`3000 / 1500 = 2` USDT/DAI

**LP Token 的用途**：
- ✅ 代表在池子中的份额
- ✅ 可以用于流动性挖矿
- ✅ 可以转让给其他地址
- ✅ 移除流动性时销毁，获得对应的代币和手续费收益

### 比例不匹配的处理

如果添加的代币比例不匹配，Router 合约会自动调整：

```solidity
// Router 合约中的处理逻辑
// 目标：根据用户提供的两种代币数量，计算最优的配对数量，保持池子比例不变

// 步骤 1: 计算如果使用用户提供的 amountADesired，需要多少 B 代币
// _quote 函数：amountB = (amountA * reserveB) / reserveA
// 即：按照当前池子比例 (reserveB / reserveA)，amountADesired 需要多少 B 代币
uint256 amountBOptimal = _quote(amountADesired, reserveA, reserveB);

// 步骤 2: 判断用户提供的 amountBDesired 是否足够
if (amountBOptimal <= amountBDesired) {
    // 情况 1: 用户提供的 B 代币足够（或刚好）
    // 使用用户提供的全部 A 代币，只使用需要的 B 代币（保持比例）
    // 多余的 B 代币会退回给用户
    (amountA, amountB) = (amountADesired, amountBOptimal);
} else {
    // 情况 2: 用户提供的 B 代币不足
    // 需要反过来计算：如果使用用户提供的 amountBDesired，需要多少 A 代币
    // _quote(amountBDesired, reserveB, reserveA) = (amountBDesired * reserveA) / reserveB
    uint256 amountAOptimal = _quote(amountBDesired, reserveB, reserveA);
    
    // 使用计算出的 A 代币数量（应该 <= amountADesired）和用户提供的全部 B 代币
    // 多余的 A 代币会退回给用户
    (amountA, amountB) = (amountAOptimal, amountBDesired);
}
```

**逻辑说明：**

这段代码的核心思想是**最大化使用用户提供的代币，同时保持池子比例不变**。

- **`_quote` 函数**：根据当前池子比例计算最优配对数量
  - `_quote(amountA, reserveA, reserveB) = (amountA * reserveB) / reserveA`
  - 含义：如果使用 `amountA` 的 A 代币，按照当前比例需要多少 B 代币

- **两种情况的处理**：
  1. **情况 1**：用户提供的 B 代币足够 → 使用全部 A，只使用需要的 B
  2. **情况 2**：用户提供的 B 代币不足 → 使用全部 B，只使用需要的 A

- **目的**：确保添加流动性后，池子比例 `(reserveA + amountA) / (reserveB + amountB)` 保持不变

**示例：**
- 期望添加：1000 DAI + 2500 USDT（比例不匹配）
- 实际添加：1000 DAI + 2000 USDT（自动调整）
- 多余的 500 USDT 会退回给用户

## ➖ 移除流动性

### 核心原则

**移除流动性不能影响价格**

移除时按照 LP tokens 的比例移除，确保价格不变。

### 计算公式

```solidity
amount0 = (liquidity * balance0) / totalSupply
amount1 = (liquidity * balance1) / totalSupply
```

**示例：**
- 当前池子：1500 DAI + 3000 USDT
- 总 LP tokens：2121
- 移除：707 LP tokens（33.3%）

**计算：**
```
amount0 = (707 * 1500) / 2121 = 500 DAI
amount1 = (707 * 3000) / 2121 = 1000 USDT
```

**结果：**
- 新池子：1000 DAI + 2000 USDT
- 新 LP tokens：2121 - 707 = 1414
- 价格保持不变：2000 / 1000 = 2 USDT/DAI

### 获得手续费收益

移除流动性时，会获得累积的手续费：

**示例：**
- 初始添加：1000 DAI + 2000 USDT，获得 1414 LP tokens
- 期间手续费累积：池子变为 1003 DAI + 2006 USDT
- 移除 1414 LP tokens：
  - 获得：1003 DAI + 2006 USDT
  - 手续费收益：3 DAI + 6 USDT

### 添加流动性流程

```
用户调用 Router.addLiquidity()
    ↓
```

```
    ↓
4. Pair 合约销毁 LP tokens
    ↓
5. Pair 合约转移代币给用户
    ↓
```

## ⚠️ 重要注意事项

### 1. 价格不变性

- **添加流动性**：必须按比例添加，否则多余的代币会被退回
- **移除流动性**：按比例移除，确保价格不变

### 2. 滑点保护

- `amountAMin` 和 `amountBMin` 用于滑点保护
- 如果实际数量少于最小值，交易会回滚

### 3. 首次添加的重要性

- 首次添加流动性决定了初始价格
- 如果价格设置不合理，可能被套利

### 4. 无常损失

- LP 需要承担无常损失风险
- 手续费收益需要覆盖无常损失才能盈利

### 5. Gas 成本

- 添加/移除流动性需要 Gas
- 频繁操作可能不划算

```
LP tokens = sqrt(amount0 * amount1)
```

**后续添加：**
```
LP tokens = min(
    (amount0 * totalSupply) / reserve0,
    (amount1 * totalSupply) / reserve1
)
```

**移除时：**
```
amount0 = (liquidity * balance0) / totalSupply
amount1 = (liquidity * balance1) / totalSupply
```
